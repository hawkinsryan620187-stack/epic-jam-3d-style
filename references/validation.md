# v0.2.0 验证记录

日期：2026-11-13。环境：macOS Apple Silicon、Blender 4.5.0、Python 3。以下为实际执行结果，不表示任意输入模型或所有 UE 版本都已验证。

## 真实模型测试

使用本项目此前由 Blender 程序制作的电脑和台灯 GLB 作为输入，两次任务均从空场景载入，运行完整整理、渲染、导出及重新导入流程。

| 项目 | 电脑 | 台灯 |
|---|---|---|
| 整理方式 | 项目材质、减面比例 0.8 | 项目材质、保持拓扑数量 |
| 输入三角面 | 2308 | 700 |
| 输出三角面 | 1834 | 700 |
| 部件 | Body | Base → LowerArm → UpperArm → Shade |
| 完整尺寸，米 | 约 0.44158 × 0.62469 × 0.45241 | 约 0.22912 × 0.34173 × 0.49700 |
| 自定义碰撞 | 单个包围盒，仅作流程测试 | 无 |
| FBX / GLB 回读 | 通过 | 四件各自通过 |
| 正、右、背、展示图 | 四张原生 1920×1080 | 四张原生 1920×1080 |

回读逐件核对了渲染网格数量、三角面数、尺寸、UV 与材质槽数量，并检查电脑 FBX 中的碰撞网格存在。台灯各件分别为 272、128、128、172 个三角面。完整装配图已人工查看，未混入 Blender 默认方块。

## 视觉复核与待修项

已查看两件资产的全部四个视角，主要体块、切面和功能部件可以辨认，图片来自真实模型，不是独立生成的视图。

电脑侧视图的机身与支撑处、台灯下转轴与底座连接处仍可见小间隙，属于进入最终资产验收前需要调整的造型问题。本轮验证自动处理管线，不将这些样例标记为最终制作验收通过，也未验证台灯运动范围。示例电脑的整体包围盒碰撞会覆盖键盘与显示器之间的空隙，实际玩法需重新选择碰撞方案。

## 边界检查

- 输入图片时拒绝运行，明确要求先得到真实网格。
- 已有非空输出目录被拒绝，原目录内容保持不变。
- 两个实际输入的全部材质通过材质规则检查；重命名过的标准 Principled 节点仍可识别。
- 贴图连接、涂层及自发光等当前不支持的材质效果被拒绝；明确填写材料角色后才允许简化。
- Python 脚本语法、Skill 元数据、模板 JSON、文档相对链接在发布前检查。

测试中发现默认启动物体混入导出范围的问题，已通过载入前清空工作场景修复，并重新执行两件完整测试。后续增强的材质检查另用两个实际输入及上述边界案例验证。

## 未覆盖的范围

UE 导入器仅完成语法检查，当前环境没有目标 UE 项目可执行；引擎导入、朝向、枢轴、碰撞、活动装配与玩法仍待实测。导入器不生成交互 Blueprint。

本轮未调用外部图生 3D 服务，未测试任意照片到最终游戏资产的自动成功率。角色绑定、开放叶片、复杂贴图/透明材质、复杂碰撞和其他 Blender 版本不在本次实测范围。

自动清单中的 `visual_review=pending`、`ue_import=not_run` 会保留；人工查看记录与引擎执行报告单独保存，避免脚本替人做风格批准。
